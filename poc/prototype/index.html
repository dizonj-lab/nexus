Your role is set in the toolbar. Roles are simulated in this prototype; real sign-in and access control come with the backend.

    
Architect console

      
      

      
      

      
Exact commands always run on rules (fast and predictable). Descriptions and free-form requests go to the model, which returns a change plan; the Action Guard reviews it before anything changes. Every reply is labelled with the engine that produced it. "/llm/v1" works when NEXUS is served from Buddy; the page proxies it to the model server there.

    
Second opinion and escalation

      

      
      
"Second opinion" in the Action Guard sends the proposed change, its findings and consequences to this model for an independent review. It is advisory: the architect decides. Leave the endpoint empty to use the console model. To use Claude, put a LiteLLM proxy on Buddy and point this at it; never paste a cloud API key into a shared page.

    
Autoscaling policy

      
      

      
Components start at the minimum, scale out when demand pushes them past the target utilization, and scale back in to the minimum once demand has stayed low for the scale-in cool-down. A component's own autoscale setting overrides this policy. Databases, caches and queues are scaled by decision, not by policy.
