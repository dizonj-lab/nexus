# Test plan · NEXUS v0.3.4

How to check each change in v0.3.4, by hand and automatically. Every manual
test starts from a fresh **New design** unless it says otherwise.

## Before you start

1. On Buddy, update and start the canvas-only instance (no sign-in):

   ```bash
   cd ~/nexus && git pull && ./deploy/canvas.sh
   ```

   Open `http://<buddy>:8091/`. The lab instance (`./deploy/buddy.sh --lab`,
   port 8089) works the same way after sign-in, from a project's canvas.
2. Hard-refresh the page (Ctrl+Shift+R) so the new canvas loads. The brand at the
   top left must read **v0.3.4**.
3. For a clean start, open the page in a private window (the canvas keeps its
   design in the browser).

Automated checks (the same scenarios, run in a headless browser with a
simulated model server):

```bash
./poc/tests/run-all.sh
```

Expected: `ALL PASSED` (about a minute; the first run also downloads the
Playwright library into `poc/tests/.pw`). Only Docker is needed: the backend
tests run in `python:3.11-slim`, the packs and browser checks in the official
Playwright image. Nothing is installed on Buddy itself.

## T1 · Second opinion on a new design no longer freezes

| # | Step | Expected |
|---|---|---|
| 1.1 | ⚙ Settings → **Second opinion and escalation**: set the endpoint and model you use (for example `gpt-oss:latest`), **Time limit** 120. Done | Settings saved |
| 1.2 | **＋ New design** → type a requirement → Next ×3 → **Create design** | The Action Guard opens for "New design: …" |
| 1.3 | Click **Get second opinion** | Within a few seconds the status changes from "Sending the facts…" to "*model* is writing · N tokens" and the number keeps rising. The page stays responsive: you can scroll the Guard and move it by its title |
| 1.4 | Wait for the answer | An opinion pill (agree / agree with conditions / disagree) and at most a few amendments ("Instead: …"). It is much faster than before, because the model no longer rewrites the whole design |
| 1.5 | If it proposed an amendment: **Implement opinion 2** | The design is created **and** the amendment applied; the console says "(amended by the second opinion: …)" |
| 1.6 | Repeat 1.2–1.3, then click **Stop** while it is writing | "No second opinion: cancelled." **Implement opinion 1** still works |
| 1.7 | Settings → Time limit **15** and choose a model that is not running (or stop Ollama), repeat 1.2–1.3 | After about 15 s: "no answer within 15 s", with a pointer to Settings |
| 1.8 | In the console: `2nd opinion` | The waiting line shows the token count; the review arrives or ends at the time limit |

Automated: `poc/tests/second-opinion.e2e.mjs` (streamed answer, a model that never
stops sending blank space, a model that never answers, Stop, time limit, page
responsiveness, amendment applied).

## T8 · Packs stay correct

All in Docker, from `~/nexus`. First define a helper in your shell:

```bash
nodec() { docker run --rm -u "$(id -u):$(id -g)" -v "$PWD":/w -w /w node:22-slim node "$@"; }
```

| # | Step | Expected |
|---|---|---|
| 8.1 | `./poc/tests/run-all.sh` | "25 pass" for the packs, "89 passed" for the backend (includes a schema check for every pack) |

## Known limits

- Packs hold the providers' documented **defaults**. Your account's quotas can
  differ (and some Regions start lower, for example API Gateway at 2,500 rps), so
  check Service Quotas before relying on a number.
- The limits were checked on 2026-11-06 against excerpts of the official pages.
  Two facts are marked "not yet confirmed" in the Limits tab.
- Rules run in the browser as named checks; OPA/Rego and the governance server
  come with WP1.
- Zones side by side with two regions side by side is wide: zoom out to see
  all lanes.
